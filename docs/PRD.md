# AI 投资参考平台 Demo PRD

## 1. 产品定位

AI 投资参考平台是一个面向投资小白的投资信息解释与研究方向发现网站。它不直接告诉用户买什么，而是帮助用户理解市场热点、行业逻辑、代表公司、基础术语和主要风险。

一句话定位：

> 为投资小白解释热点行业、代表公司和关键投资概念，帮助用户找到值得继续研究的方向。

## 2. 目标用户

主要用户是没有系统投资经验的小白投资者。他们通常看不懂财经新闻、K 线、估值、财报和行业术语，容易被热点和所谓“推荐股”吸引，但缺少判断框架。

次要用户是有一定投资经验但暂时没有方向的人。他们需要快速了解近期市场关注方向、行业线索、代表公司、趋势逻辑和风险提示。

## 3. Demo 目标

Demo 版本用于演示产品价值，不追求完整真实数据能力。

本阶段需要做到：

- 可通过 GitHub Pages 公网访问。
- 第一屏清楚表达产品定位和风险边界。
- 展示“热点行业观察”“ETF 指标解读”和“行业 / 公司查询”三块核心信息。
- 提供面向小白的术语解释和风险提示。
- 页面专业、清晰、可信，适合桌面端和移动端访问。
- 所有投资相关内容标注“仅供参考，不构成投资建议”。

本阶段暂不做：

- 用户登录。
- 真实交易。
- 实时行情。
- 真实 AI 接口。
- 后端服务。
- 数据库。
- 付费功能。
- 个性化资产配置。

## 4. 核心原则

### 小白优先

行业、公司、指标和术语都要用普通语言解释。先让用户看懂，再引导用户继续研究。

### 信息分层

页面先给出结论和概要，再展示原因、产业链、指标、误区和风险，避免一次性堆叠过多专业信息。

### 参考而非荐股

产品措辞使用“观察”“研究线索”“代表公司”“风险提示”等表达，避免“买入”“卖出”“稳赚”“目标价”等投资建议式表达。

### 强调风险和证据

每个热点和趋势判断都应配套说明风险因素。后续正式版本需要为观点提供来源、依据和置信度。

## 5. 信息架构

Demo 采用单页网站结构：

1. 顶部导航。
2. 首屏市场观察概览。
3. 热点行业观察。
4. 行业详情解读。
5. 代表公司观察。
6. 具体 ETF 指标解读。
7. 行业 / 公司查询。
8. 投资术语解释。
9. 风险提示和免责声明。

## 6. 核心模块

### 6.1 首屏概览

首屏需要让用户快速理解网站价值：

- 网站名称：AI 投资参考平台。
- 核心说明：为投资小白解释热点行业、代表公司和关键投资概念。
- 明确边界：不提供买卖建议，不承诺收益，内容仅供学习和研究参考。
- 展示演示数据的整体状态，例如热点行业数量、术语数量、风险提示覆盖情况。

### 6.2 热点行业观察

目标是让用户快速知道市场可能关注哪些方向，并理解为什么关注。

Demo 展示 5 个样例行业：

- AI 算力。
- 半导体。
- 人形机器人。
- 低空经济。
- 创新药。

每个行业卡片包含：

- 行业名称。
- 一句话解释。
- 当前关注度。
- 为什么被关注。
- 代表方向。
- 主要风险。
- 适合小白理解的标签。

所有数据均标注为“演示样例，不代表实时市场热点或投资建议”。

### 6.3 行业详情解读

用户选择行业后，页面展示结构化解释：

- 这个行业是做什么的。
- 为什么最近受到关注。
- 产业链结构。
- 代表公司类型。
- 适合关注的指标。
- 小白容易误解的点。
- 风险提示。
- 继续学习关键词。

### 6.4 代表公司观察

目标是给用户提供研究对象，而不是买卖建议。

公司卡片包含：

- 公司名称。
- 所属行业。
- 公司主要做什么。
- 与热点行业的关系。
- 可以关注的业务指标。
- 潜在机会。
- 主要风险。
- 研究提示。

禁止使用：

- 推荐买入。
- 强烈看好。
- 必涨。
- 目标价。
- 抄底。
- 满仓。

### 6.5 具体 ETF 指标解读

目标是把“小白解释”嵌入具体资产信息，而不是只放在固定术语区。

Demo 展示一个 ETF 样例：

- 沪深300ETF。
- 代码 510300。
- 宽基 ETF。
- 演示数据，不代表实时行情。

页面展示指标：

- 跟踪指数。
- 基金规模。
- 管理费率。
- 跟踪误差。
- 市盈率 PE。
- 成交额。
- 前十大权重。
- 最大回撤。

交互规则：

- 用户悬停指标时，展示一句话短提示。
- 用户点击指标时，在右侧解释面板展示详细说明。
- 解释内容包含“这个指标是什么”“小白怎么看”“需要一起看的信息”“常见误区”和风险提示。
- 指标解释不提供买卖建议，不使用收益承诺或目标价。

### 6.6 行业 / 公司查询

目标是让用户主动输入行业或公司，获得结构化解释。

Demo 阶段不接入真实 AI，采用静态样例匹配。用户输入命中样例关键词时，展示对应解释；未命中时，提示当前 Demo 暂未收录，并推荐可尝试的演示关键词。

查询结果包含：

- 查询对象。
- 通俗解释。
- 当前关注逻辑。
- 相关行业。
- 代表公司类型。
- 关键指标。
- 小白需要先理解的概念。
- 风险提示。

### 6.7 投资术语解释

术语解释是面向小白的关键差异点。

Demo 先覆盖：

- K 线。
- 日线。
- 成交量。
- 市盈率 PE。
- 市净率 PB。
- 估值。
- 龙头公司。
- 板块。
- 概念股。
- 基本面。
- 技术面。
- 回撤。

每个术语包含：

- 术语名称。
- 一句话解释。
- 小白理解版。
- 常见误区。

## 7. 合规与风险边界

页面底部和关键投资信息模块旁必须展示：

> 本平台内容仅用于投资学习和信息参考，不构成任何证券、基金、期货或其他金融产品的投资建议。投资有风险，决策需谨慎。

产品边界：

- 不提供买入 / 卖出建议。
- 不承诺收益。
- 不做个性化资产配置。
- 不代替专业投顾服务。
- 不展示虚假的实时行情。
- Demo 数据必须明确标注为演示样例。
- ETF 指标数值必须标注为演示样例，不能被包装成真实行情或正式研究结论。

## 8. Demo 数据策略

Demo 采用静态演示数据，原因是：

- 开发快。
- 不依赖第三方金融 API。
- GitHub Pages 可直接托管。
- 避免实时数据准确性问题。
- 便于演示产品结构和交互。

当前数据范围：

- 5 个热点行业样例。
- 每个行业 3 个代表公司样例。
- 1 个 ETF 指标解读样例。
- 12 个投资术语。
- 若干关键词查询结果。

## 9. 视觉风格

目标风格：

- 专业。
- 清晰。
- 可信。
- 低压力。
- 适合反复阅读和查询。

避免：

- 过度营销感。
- 大面积红绿涨跌刺激。
- “暴涨”“牛股”“稳赚”等表达。
- 复杂交易终端风格。
- 过度装饰化金融大屏。

建议：

- 浅色背景。
- 高对比文字。
- 使用克制的蓝、绿、橙、红作为信息状态色。
- 卡片半径不超过 8px。
- 信息分区清楚，移动端不溢出、不重叠。

## 10. 技术方案

Demo 使用纯静态技术：

- HTML。
- CSS。
- JavaScript。
- Node.js 内置测试模块。
- GitHub Pages。

选择原因：

- 不需要构建服务器。
- 不需要安装第三方依赖。
- 可直接部署到 GitHub Pages。
- 适合快速演示。
- 后续可以平滑迁移到 React、Vite 或 Next.js。

## 11. 验收标准

Demo 完成后需满足：

- 可以通过 GitHub Pages 公网访问。
- 页面加载正常。
- 桌面端和移动端布局稳定。
- 能看到“热点行业观察”。
- 能看到“ETF 指标解读”。
- 能看到“行业 / 公司查询”。
- 能看到“小白术语解释”。
- 点击 ETF 指标后，右侧解释面板能更新对应的小白说明。
- 每个投资相关模块都有风险提示。
- 所有 Demo 数据明确标注为演示样例。
- 没有明显文字溢出或元素重叠。
- README 说明项目定位、运行方式和免责声明。
- 测试脚本通过。

- 做“看不懂这个词”即时解释。
- 做来源引用和证据链。
- 做风险等级提示。
